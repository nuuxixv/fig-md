# Fig.md — 설계 스펙

## 0. 한 문장 정의

피그마 프레임을 **노션 페이지처럼** 쓰는 마크다운 문서 에디터 플러그인.
마크다운을 **투입(import) → 캔버스에서 GUI로 편집(edit) → 마크다운으로 출력(export)** 하는
라운드트립 허브. 표와 양방향(export)을 모두 지원한다.

## 1. 배경 (Why)

### 1.1 사용자 워크플로우

소유자(테크니컬 PM)의 실제 문서 작업 흐름:

1. Claude로 기획 구체화
2. Claude가 마크다운 초안 작성
3. **마크다운 초안을 피그마에서 편집·고도화** ← 이 도구가 사는 자리
4. 고도화된 마크다운을 협업툴·Claude·노션에 다시 올림(공유)

3번에서 마크다운을 시각적으로 다듬고, 4번을 위해 다시 깨끗한 마크다운으로 뽑아내야 한다.
즉 **입력·편집·출력이 모두 마크다운을 축으로** 돌아야 한다.

### 1.2 기성 플러그인이 못 채우는 공백 (2026-07-22 시장 조사)

세 조건 — ①표 지원 ②양방향(export) ③편집 가능한 구조 블록 — 을 **동시에** 만족하는
기성 플러그인은 없다. 하나를 잡으면 하나를 놓친다.

| 플러그인 | 표 | 양방향 | 한계 |
|---|---|---|---|
| Markly (오픈소스) | ✗ | ○ (md↔텍스트레이어) | 표 미지원. export가 텍스트 평문 긁기 — 구조 없음 |
| Markdown to Figma Layers | ○ | ✗ | 임포트 전용(단방향) |
| Markdown Table Importer / CSV to Table | ○ | ✗ | 표만, 임포트 전용 |
| MD to Figma | ✗ | ○ | 문서가 아니라 디자인시스템 토큰 동기화용 |
| CopyDoc (유료) | △ | ○ | 텍스트 내용 갱신 중심. 표 라운드트립 불확실 |

**핵심 공백:** 표를 하는 도구는 죄다 단방향이고, 양방향 도구(Markly)는 표를 못하며
export가 구조 없는 평문 긁기다. "구조 미러 + 표 + 양방향"을 채운 물건이 없다.

**참고 자산:** Markly가 오픈소스(github.com/darasoba/Markly)라, 마크다운 파서·폰트
로딩·텍스트 스타일 매핑 부분은 참고 가능. 표·구조·역조립은 새로 설계한다.

## 2. 목표 / 비목표

### 2.1 목표 (v1)

- 마크다운 텍스트를 피그마 프레임 안의 구조화된 블록으로 **렌더**한다.
- 렌더된 블록을 캔버스에서 **편집**한다: 텍스트 수정(네이티브), 블록 추가·삭제·재배치(GUI).
- 편집된 프레임을 다시 **깨끗한 마크다운으로 출력**한다(라운드트립).
- **표**를 임포트·편집·익스포트 전 구간에서 지원한다.

### 2.2 비목표 (v1 명시적 제외)

- 토글 접기(Notion 토글) — 표준 마크다운 대응물 없음. 라운드트립을 깨므로 제외.
- 표의 세부 편집(행/열 삭제·병합 등) — v1은 표 렌더·텍스트편집·출력까지만.
- 실시간 양방향 바인딩(패널 md ↔ 캔버스 동시 동기화) — 불필요. 명시적 버튼으로 충분.
- 디자인시스템 토큰(변수·스타일) 동기화 — 용도가 다름.
- 임의로 손으로 그린 도형의 마크다운 역해석 — 꼬리표 없는 이물질은 무시+경고.
- **제목(heading) 안의 인라인 서식(굵게/기울임/코드/링크) 왕복** — 제목은 렌더 시 전체
  Bold, 출력 시 평문 재해석으로 고정한다(3.3 참조). 문단·목록 항목은 v1에서 지원.

## 3. 핵심 아키텍처 — "꼬리표 달린 오토레이아웃 미러"

이 플러그인의 안정성은 **"임의의 피그마 화면을 역파싱하지 않는다"**는 원칙에서 나온다.
대신 플러그인이 그린 블록마다 꼬리표(메타데이터)를 심고, 출력은 그 꼬리표를 따라
**역추측이 아니라 정확한 재조립**으로 수행한다.

### 3.1 페이지 = 오토레이아웃 프레임

- 문서 한 개 = 세로 오토레이아웃 프레임 1개("페이지 프레임").
- 페이지 프레임의 **직속 자식 1개 = 블록 1개**.
- 블록 순서 = 자식 순서. → **드래그로 블록을 위아래로 옮기면 그게 곧 문서 순서 변경.**
- 오토레이아웃이 "있으면 좋은 것"이 아니라 **이 구조의 엔진**이다(블록 삽입 시 자동 리플로).

### 3.2 블록 = 꼬리표 달린 노드

각 블록 노드의 `pluginData`(네임스페이스 `figmd`)에 최소 다음을 저장:

```
figmd:version   스키마 버전 (예: "1")
figmd:block     블록 타입 (heading | paragraph | list | quote | divider
                            | table | code | image)
figmd:meta      블록별 구조 메타 (JSON 문자열)
```

블록별 `meta` 예:
- heading → `{ level: 1|2|3 }`
- list → `{ ordered: bool }` (항목별 들여쓰기 레벨은 항목 노드 meta에)
- code → `{ lang: string }`
- table → `{ rows, cols }` (셀 텍스트는 각 셀 텍스트노드에서 읽음)
- image → `{ src, alt }`

텍스트 내용은 **별도 저장하지 않는다.** 네이티브 피그마 텍스트 노드에 그대로 있으므로,
캔버스에서 글자를 고치면 출력 시 그 텍스트 노드를 읽어 반영한다.
(= 텍스트 편집은 자동으로 양방향)

### 3.3 인라인 서식의 왕복

굵게/기울임/인라인코드/링크는 피그마 텍스트노드의 **문자 범위 스타일**(fontWeight,
italic, fills, hyperlink)로 렌더하고, 출력 시 문자 범위를 스캔해 `**`, `*`, `` ` ``,
`[텍스트](url)`로 역조립한다. 링크 URL은 텍스트노드 range의 hyperlink에 저장.
**문단**과 **목록 항목**(마커/체크박스 접두어 제외한 본문 범위)에서 이 왕복이 적용된다.

**v1 한계(문서화):** **제목(heading)** 안의 인라인 서식은 왕복 대상이 아니다 — 렌더는
전체를 Bold로 칠하고, 출력은 문자 범위를 읽지 않고 평문(`parseInlines`)으로 재해석한다.
즉 `# **A** B`처럼 제목 안에 부분 강조를 넣어도 출력 시 `# A B`처럼 평문화된다. 제목은
문서 구조상 이미 Bold이므로 실무 영향이 적다고 판단해 v1에서는 의도적으로 제외했다.

## 4. 동기화 모델 — 접근법 1 (명시적 임포트/익스포트)

라이브 실시간 동기화는 **채택하지 않는다**(오버엔지니어링·충돌·성능). 대신:

- 패널 버튼 둘:
  - **`마크다운 → 렌더`**: 패널 textarea의 md를 파싱해 페이지 프레임을 생성/갱신.
  - **`익스포트 → 마크다운`**: 선택된(또는 최근) 페이지 프레임의 꼬리표 트리를 순회해
    md 문자열 생성 → 패널에 표시 + 클립보드 복사.
- 두 버튼 사이에 캔버스에서 자유롭게 편집한다. 익스포트는 **누를 때** 현재 상태를 읽는다.
- 이 모델이 사용자 워크플로우 4단계(투입→고도화→내보내기)와 정확히 일치한다.

### 4.1 재렌더 정책 (v1)

`마크다운 → 렌더`를 다시 누르면 **해당 페이지 프레임을 전체 재생성**한다(단순·예측 가능).
즉 캔버스에서 준 손질은 재렌더 시 md 기준으로 덮어써진다.
(블록 diff 기반 "스마트 재렌더"로 캔버스 손질 보존은 v2 후보 — v1은 하지 않는다.)

## 5. 블록 편집 GUI

편집은 "손으로 아무 도형이나 그리기"가 아니라 **플러그인이 관리하는 블록 안**에서 이뤄진다.

- **텍스트 편집:** 네이티브. 텍스트노드 더블클릭 후 타이핑.
- **블록 추가:** 패널 또는 캔버스의 "+" 메뉴에서 블록 타입 선택(구분선·표·코드블록 등)
  → 꼬리표가 붙은 블록이 현재 선택 위치에 삽입됨.
- **블록 재배치:** 오토레이아웃 안에서 드래그(피그마 기본 동작). 순서가 곧 문서 순서.
- **블록 삭제:** 노드 삭제(피그마 기본 동작).
- **이물질 방어:** 꼬리표 없는 노드(사용자가 직접 그린 도형 등)가 페이지 프레임 안에 있으면
  익스포트 시 **무시하고, 무엇을 건너뛰었는지 경고**로 알린다(조용한 누락 금지).

## 6. v1 마크다운 범위 (B안)

| 문법 | 렌더 | 편집 | 익스포트 |
|---|---|---|---|
| 제목 `#`~`###` | ○ | ○ | ○ |
| 본문 문단 | ○ | ○ | ○ |
| 굵게/기울임 `**` `*` | ○ | ○ | ○ |
| 목록(순서/비순서) | ○ | ○ | ○ |
| 목록 들여쓰기 중첩 | ○ | ○ | ○ |
| 인용/콜아웃 `>` | ○ | ○ | ○ |
| 구분선 `---` | ○ | ○ | ○ |
| 표 | ○ | 텍스트만 | ○ |
| 링크 `[]()` | ○ | ○ | ○ |
| 인라인 코드 `` ` `` | ○ | ○ | ○ |
| 코드블록 ```` ``` ```` | ○ | ○ | ○ |
| 이미지 `![]()` | ○ | — | ○ |
| 체크박스 `- [ ]` | ○ | ○ | ○ |

**중첩 목록은 들여쓰기(2칸) 방식.** 협업툴·Claude·노션 어디로 내보내도 살아남는다.
(토글 접기는 라운드트립을 깨므로 v1 제외 — 2.2 참조.)

표의 "굵게/기울임" 열은 **제목을 제외한 모든 텍스트 블록**(문단·목록 항목)에 적용되는
왕복이다. 제목 안의 굵게/기울임/링크/코드는 v1에서 평문으로 고정된다(2.2, 3.3 참조).

## 7. 컴포넌트 구조

```
fig-md/
  manifest.json          Figma 플러그인 매니페스트
  src/
    code.ts              메인 스레드(피그마 문서 조작). UI와 postMessage로 통신
    ui.html              패널 UI 셸
    ui.ts                패널 로직(md 입력·버튼·미리보기·클립보드)
    core/
      parse.ts           md 문자열 → 블록 AST (markdown-it 기반)
      render.ts          블록 AST → 피그마 노드 트리(꼬리표 심기)
      export.ts          페이지 프레임(꼬리표 트리) → md 문자열
      blocks/            블록 타입별 렌더러/익스포터 (heading, table, ...)
      tag.ts             pluginData 읽기/쓰기 헬퍼 (네임스페이스 figmd)
  docs/specs/            이 스펙 등
  package.json  tsconfig.json  (esbuild 번들)
```

### 7.1 단위별 책임 (한 파일 = 한 목적)

- `parse.ts`: 입력은 md 문자열, 출력은 우리 내부 블록 AST. 피그마를 모른다.
- `render.ts`: 입력은 블록 AST, 출력은 피그마 노드. 마크다운 문법을 모른다.
- `export.ts`: 입력은 꼬리표 달린 피그마 노드 트리, 출력은 md 문자열. `parse`의 역함수.
- 세 단계가 **내부 블록 AST**라는 단일 계약으로만 연결된다 → 각자 독립 테스트 가능.

## 8. 표 라운드트립 (최대 난관, v1 초점)

- **렌더:** 표 = 오토레이아웃 그리드(행 프레임들 → 셀 텍스트노드들). 표 프레임에
  `figmd:block=table`, `figmd:meta={rows,cols}`. 각 셀에 `figmd:cell={r,c}` 꼬리표.
- **편집:** 셀 텍스트를 네이티브로 수정(v1은 여기까지. 행/열 추가·삭제는 v2).
- **익스포트:** 표 프레임을 만나면 `rows×cols`를 읽고, 셀 꼬리표 순서대로 텍스트를 모아
  `| ... | ... |` + 헤더 구분선(`|---|---|`)으로 재조립.

## 9. 기술 스택

- Figma Plugin API + **TypeScript**.
- UI: iframe(HTML/CSS + 약간의 TS). 무거운 프레임워크 없이 시작.
- 마크다운 파싱: **직접 구현(hand-rolled)** — v1 문법이 작아 감당 가능하고,
  `parse`와 `serialize`가 서로 정확한 역함수가 되어 라운드트립이 안정적이다.
  외부 의존성 0, 순수 함수로 Node에서 완전 테스트 가능. (2026-07-22 결정: markdown-it 대신)
- 번들러: **esbuild**(빠름, 설정 최소). `design-extractor` 선례 구조 참고.

## 10. 리스크 & 대응

| 리스크 | 대응 |
|---|---|
| 표 라운드트립 정확도 (최대 난관) | 셀별 꼬리표로 재조립. v1의 1순위 테스트 대상 |
| 폰트 로딩 비동기 실패 | 렌더 전 필요한 폰트 `loadFontAsync` 선(先)로드 + 폴백. Markly 패턴 참고 |
| 이물질 블록 누락 | 익스포트 시 무시하되 **경고로 명시**(조용한 누락 금지) |
| 인라인 서식 중첩(굵게+링크 등) | 문자 range 스캔을 우선순위 규칙으로 정규화. 엣지케이스 테스트 셋 확보 |
| 전체 재렌더로 캔버스 손질 소실 | v1은 정책으로 수용(문서화). 스마트 재렌더는 v2 |

## 11. 성공 기준 (측정 가능)

1. 대표 PRD 마크다운(제목·콜아웃·표·목록·코드블록 포함)을 렌더 → 캔버스에서
   문구 수정·구분선 1개 추가·블록 1개 이동 → 익스포트했을 때,
   **의미가 보존된 유효한 마크다운**이 나온다(협업툴/노션에 붙여 깨지지 않음).
2. 표가 임포트→익스포트 왕복에서 행·열·셀 내용을 **손실 없이** 유지한다.
3. 꼬리표 없는 이물질이 있어도 크래시 없이 익스포트되고, 건너뛴 항목이 경고된다.
